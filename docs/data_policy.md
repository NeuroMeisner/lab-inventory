# Политика обработки персональных данных — Lab Inventory

**Версия:** 1.0  
**Дата:** Ноябрь 2026  
**Ответственный:** Администратор системы

## 1. Общие положения

Настоящая политика определяет порядок обработки персональных данных (ПДн) пользователей системы учёта лабораторных расходников «Lab Inventory».

## 2. Состав обрабатываемых ПДн

Система хранит следующие персональные данные:

| Поле | Назначение | Срок хранения |
|------|-----------|---------------|
| `google_email` | Идентификация пользователя при входе | 5 лет после деактивации |
| `telegram_id` | Связка с Telegram-ботом для уведомлений | 5 лет после деактивации |
| `full_name` | Отображение имени в интерфейсе и отчётах | 5 лет после деактивации |
| `role` | Права доступа (user/admin) | Бессрочно (часть истории) |
| `is_active` | Статус аккаунта | Бессрочно |
| `deactivation_reason` | Причина деактивации | 5 лет после деактивации |
| `pii_removed_at` | Дата удаления PII | Бессрочно |

## 3. Цели обработки

- **Идентификация:** вход в систему через Google OAuth или dev-режим
- **Авторизация:** определение прав доступа (user/admin)
- **Уведомления:** отправка push-уведомлений через Telegram-бот
- **Подотчётность:** привязка действий (списания, перемещения) к конкретному сотруднику
- **Аудит:** расследование инцидентов и проверок грантов

## 4. Срок хранения ПДн

### 4.1. Активные пользователи
ПДн хранятся бессрочно, пока аккаунт активен.

### 4.2. Деактивированные пользователи
ПДн деактивированных пользователей (уволенных, переведённых) хранятся **5 лет** после деактивации для целей:
- Подотчётности по грантам (типичный срок хранения финансовых документов)
- Расследования инцидентов (кто списал реактив, если обнаружена проблема)
- Проверок аудиторов

По истечении 5 лет ПДн удаляются автоматически (планировщик) или вручную администратором.

### 4.3. История транзакций
История действий пользователя (`transactions`, `audit_log`) сохраняется **бессрочно**, даже после удаления PII. Это необходимо для:
- Финансовой отчётности по грантам
- Расследования инцидентов
- Соответствия требованиям аудита

При удалении PII история остаётся с `user_id`, но без имени/email/Telegram.

## 5. Права субъекта ПДн

Субъект ПДн (сотрудник) имеет право:

### 5.1. Запросить удаление ПДн
Сотрудник может подать письменный запрос администратору на удаление персональных данных. Процедура:

1. Сотрудник подаёт запрос администратору (устно или письменно)
2. Администратор открывает PWA → Admin → Users
3. Находит деактивированного пользователя
4. Нажимает кнопку **"Remove PII"**
5. Вводит причину (например, "Запрос субъекта от 15.11.2026")
6. Подтверждает удаление

Результат:
- `google_email`, `telegram_id`, `full_name` → NULL или "Deleted user #ID"
- `is_active` → false (если ещё не было)
- `pii_removed_at` → текущая дата
- `token_version` → инкремент (все сессии отозваны)
- История транзакций сохраняется

### 5.2. Запросить копию своих данных
Сотрудник может запросить выгрузку своих данных (email, имя, список действий). Администратор формирует CSV из `audit_log` и `transactions` за последний год.

### 5.3. Отозвать согласие на обработку
Сотрудник может отозвать согласие, подав запрос на удаление PII (см. 5.1). После удаления PII система не может идентифицировать пользователя, обработка прекращается.

## 6. Доступ к ПДн

| Роль | Видит активных | Видит деактивированных | Может удалить PII |
|------|----------------|------------------------|-------------------|
| Обычный сотрудник | Да | **Нет** | Нет |
| Администратор | Да | Да | Да |

**Важно:** деактивированные пользователи не видны обычным сотрудникам в списках, подсказках, отчётах. Это защита от утечки информации об уволенных.

## 7. Меры защиты

- **Шифрование:** БД хранится на сервере с доступом только для приложения
- **JWT-токены:** access (1 час) + refresh (30 дней), отзыв через `token_version`
- **DEV_MODE:** ограничен по IP и email, красный баннер в UI
- **Rate limiting:** защита от перебора кодов связки
- **Аудит:** все изменения ПДн логируются в `audit_log` с указанием админа и причины

## 8. Автоматическое удаление ПДн

Планировщик ежедневно проверяет деактивированных пользователей старше 5 лет и автоматически удаляет PII:

```python
async def cleanup_old_deactivated_users(session: AsyncSession) -> None:
    cutoff = datetime.now(timezone.utc) - timedelta(days=5*365)
    users = await session.execute(
        select(User).where(
            User.is_active.is_(False),
            User.deactivated_at < cutoff,
            User.pii_removed_at.is_(None),
        )
    )
    for user in users.scalars():
        user.google_email = None
        user.telegram_id = None
        user.full_name = f"Deleted user #{user.id}"
        user.pii_removed_at = datetime.now(timezone.utc)
        user.token_version += 1
    await session.commit()
