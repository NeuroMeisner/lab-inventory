# Модуль 3: Telegram-бот

## Режимы работы

| Режим | Когда | Что работает |
|---|---|---|
| **MOCK** | `BOT_TOKEN` пустой | Приём уведомлений от бэкенда (вебхук), логирование, `/health`, `/mock/notifications`. Команды Telegram отключены |
| **LIVE** | `BOT_TOKEN` задан | Всё из MOCK + команды бота через polling |

## Запуск

В составе системы:
```bash
docker compose up -d --build telegram-bot
docker compose logs -f telegram-bot    # смотреть, что происходит
```

В MOCK-режиме можно проверить связку «бэкенд → бот» прямо сейчас:
```bash
# Имитируем уведомление (секрет должен совпадать с INTERNAL_API_SECRET):
curl -X POST http://localhost:8080/bot/webhook \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: change-me-internal-secret" \
  -d '{"event":"low_stock","recipient_telegram_ids":[1],"payload":{"name":"Acetone","unit":"mL","total_stock":100,"min_stock":500,"auto_order_created":true}}'

# Смотрим, что принято:
curl http://localhost:8080/mock/notifications
```
А можно и по-настоящему: спишите в PWA/Swagger ацетон ниже минимума — бэкенд сам отправит `low_stock`, и оно появится в `/mock/notifications`.

## Включение настоящего бота (когда будете готовы)

1. В Telegram найдите **@BotFather** → отправьте `/newbot` → придумайте имя и логин → скопируйте токен вида `123456789:AAE...`
2. В файле `.env` в корне проекта впишите: `BOT_TOKEN=ваш_токен`
3. Перезапустите: `docker compose up -d --build telegram-bot`
4. В логах появится `Starting in LIVE mode`. Откройте бота в Telegram и отправьте `/start`.

## Команды

| Команда | Описание |
|---|---|
| `/start` | Приветствие и инструкция по связке |
| `/link <код>` | Связать аккаунты (код из PWA: Home → Link Telegram) |
| `/search <название>` | Поиск → кнопки позиций → карточки упаковок → [📝 Списать через веб] / [🔒 Собираюсь взять] |
| `/mypackages` | Мои вскрытые упаковки (за 30 дней) |
| `/pending` | Мои неразмещённые упаковки (с кнопкой в PWA) |
| `/help` | Справка |

## Уведомления от бэкенда (ТЗ 3.4)

`low_stock`, `expiry_warning_30d`, `package_expired`, `pending_placement`, `reserve_expiring`, `purchase_order_due` — все обрабатываются и рассылаются получателям из `recipient_telegram_ids` (бэкенд сам определяет, кого уведомить). Защита — заголовок `X-Webhook-Secret`.

## Тесты

```bash
docker compose run --rm telegram-bot pytest -v
```
Тесты используют встроенную мини-копию бэкенда: авторизация и кэш токенов, повтор при 401, связка аккаунтов, резервирование, форматирование всех уведомлений, защита вебхука секретом.

## Принятые решения / отклонения от ТЗ

1. **Без прямого доступа к БД** — бот ходит только в REST API бэкенда (проще деплой и безопасность).
2. Получение обновлений Telegram — **polling** (не требует публичного HTTPS-домена); для уведомлений от бэкенда внутри бота поднят вебхук-сервер в закрытой Docker-сети.
3. Авторизация действий пользователя: бот обменивает `telegram_id` на JWT через `POST /auth/telegram` с заголовком `X-Bot-Secret` (эндпоинт доверяет только нашему боту); токены кэшируются и автоматически продлеваются.
4. Все тексты — на английском (международная лаборатория).
5. Карточки упаковок в боте отправляются отдельными сообщениями (по одной на упаковку) — на телефоне так удобнее, чем одна длинная простыня с общими кнопками.
